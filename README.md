# 可编辑教学图

给教师使用的 Codex 三阶段技能包：**教学 PPT 拆解规划 → AI 教学主体图 → 在独立聊天中复刻为可编辑 PPTX**。

三个技能有固定顺序和简短名称，安装后复制下方调用语句即可。先新建一个空文件夹作为教学主题项目：一个聊天完成规划、确认和生图；另一个聊天按需复刻每张图。第三阶段可暂时不做，前两阶段仍保存好后续复现资料。

| 顺序 | 技能 | 输入 | 交付 |
|---|---|---|---|
| 1 | `$teach-1-plan` | 教学 PPT/PPTX、保留项 | 拆图数量、标题、原页覆盖映射、逐图完整提示词 |
| 2 | `$teach-2-gen` | 确认后的规划、用户命名的文件夹 | 教学图、准确复现清单、生成记录、复现交接.md |
| 3 | `$teach-3-ppt` | 确定版本原图、清单、可选模板 | 对象级可编辑 PPTX、页面预览、验证报告 |

图片生成阶段交付的是位图。复刻后普通文字、代码、卡片、表格和连接线应成为相应原生对象；复杂插图可保留为独立图片，交付报告须说明编辑范围及差异。

## 从空文件夹开始：两个聊天怎么用

1. 在自己的项目集合目录下，新建一个用教学主题命名的空文件夹，例如“按键控制教学图”，在 Codex 中将它打开为项目。已有个人级技能安装可直接使用；否则先按下文安装或建立项目技能链接。教学任务材料放这个新项目内，不放本技能发布仓库。
2. 在这个项目的第一个聊天上传 PPT，复制下面的启动语句。智能体检查实际 PPT 页数，规划应拆成多少张教学图，为各图起标题并给出完整提示词。PPT 页数与教学图数量分别报告，不要求一页对应一图。
3. 核对规划，回答确认范围及生图任务文件夹名称。同一个聊天收到实际确认后调用 teach-2-gen，把图片和配套资料保存到新项目内。无需每张图重复确认已经授权的生成任务；有内容冲突时先解决。
4. 确认最终图片版本后，可以就此结束，也可以以后在这个项目中另开一个聊天，读取复现交接，逐图复刻。默认每张图输出一个同名 PPTX；需要时也可以明确要求合并。只生图时不自动启动复现或创建空复现任务目录。

第一个聊天的启动语句（替换路径后直接复制）：

```text
这是一个新的教学图项目，项目目录是：[填写新建空文件夹的绝对路径]。
请将本次输入、规划、提示词、图片和交接资料都保存在这个项目内。
按实际需要建立生图工作区和项目说明，不预建空复现目录或为每个素材文件夹创建README。

先用 $teach-1-plan 分析我上传的PPT，报告实际PPT页数和检查范围，
规划应拆成多少张教学图，给出逐图标题、来源页映射及每图完整版提示词。
先让我确认规划，并询问生图任务文件夹名称。

收到我的明确确认和文件夹命名答复后，在这个聊天继续用 $teach-2-gen 生成确认范围内的图片。
图片按确认的逐图标题命名，保存到本项目生图工作区的用户命名文件夹。
同时保存规划、完整提示词、准确复现清单及复现交接.md。
本次不自动复现；复现是可选的后续任务。
我确认最终图片版本后，请提供填好真实路径的、新聊天逐图复现调用语句。
```

启动语句授权了“确认后生图”，但不能跳过用户实际确认或擅自替用户命名任务文件夹。即使暂时不复现，也保留确定版本原图、完整提示词、准确文字/代码/公式、连接关系、独立素材及已知问题，方便以后继续。

## 技能引用为什么显示成中文标签

Codex 可能把输入框中的技能引用显示为带图标的中文标签，例如“1 教学图规划”；它对应技能显示名，实际调用名仍是 `teach-1-plan`。在仓库复制下方代码块里的纯文本即可，`$teach-1-plan`、`$teach-2-gen`、`$teach-3-ppt` 不需要复制图标或截图，也不需要把每个 SKILL.md 全文粘进聊天。技能须已安装且能被当前项目发现。

## 安装

### 方法一：让 Codex 安装（推荐）

在具备 `skill-installer` 的 Codex 中复制：

```text
用 $skill-installer 从公开仓库 zcq19991029/editable-teaching-graphics 的 main 分支安装以下三个技能：
.agents/skills/teach-1-plan
.agents/skills/teach-2-gen
.agents/skills/teach-3-ppt

三个技能必须同时安装并保留全部 references 和 agents 文件。
如果已经存在同名技能，先核对原件和链接；不要直接覆盖或创建重复入口。
安装后检查三个技能名称及相对引用，并报告实际安装位置。
```

安装后在下一条消息调用技能；若没有出现，重开聊天或重启 Codex。当前安装器默认安装到 `$CODEX_HOME/skills`（未设置时为 `~/.codex/skills`）；安装器路径与用户级 `.agents/skills` 发现路径应按实际环境核对。

### 方法二：在项目中使用

有 Git 时执行：

```bash
git clone https://github.com/zcq19991029/editable-teaching-graphics.git
cd editable-teaching-graphics
```

在这个目录打开 Codex，技能原件位于本仓库 `.agents/skills/`。要在自己的教学项目中使用，可让 Codex将项目 `.agents/skills/teach-*` 或用户 `~/.agents/skills/teach-*` 目录链接到这三个完整技能文件夹。Windows 使用 Junction，macOS/Linux 使用符号链接；不要使用 `.lnk` 文件。已有同名入口时先核对，换电脑重新建立链接。不要在仓库和用户目录重复安装同名副本。

安装与目录发现规则参考 [Codex 官方技能文档](https://developers.openai.com/codex/skills/)。

## 外部依赖

本仓库只提供教学工作流技能，不捆绑模型服务、OCR 凭据、PPT 模板或第三方工具实现。

- **规划**：需要当前环境中适用的 PPT 读取与渲染能力，例如已安装的 `presentations` 或 `officecli-pptx`。只读标题不能代替检查实际页面。
- **生图**：需要当前环境可用的 `imagegen` 技能及实际生图工具。安装本包不会自动开通生图能力，也不固定宣称某个型号是“最新模型”。
- **复现**：必须另装 [image-to-editable-ppt](https://github.com/ningzimu/image-to-editable-ppt-skill)，并按其安装说明准备 `editppt` CLI。该技能是独立上游依赖，不复制进本仓库。

复现依赖可复制此段让 Codex 安装和诊断：

```text
用 $skill-installer 从 ningzimu/image-to-editable-ppt-skill 的 main 分支安装 skills/image-to-editable-ppt。
已安装时先核对版本和入口，不覆盖我的配置。
然后读取该技能及其 references/cli-helper.md，按当前安装说明检查或安装 editppt CLI，运行 editppt --help 和 editppt doctor，报告可用性及缺失依赖。
不要把仅安装技能文件写成复现环境已通过。
```

多页复现按上游要求使用 page worker，需要支持子代理的环境；不支持时报告限制。OCR 与图像后台是否可用由该依赖运行时诊断，不把本包安装成功当作这些服务已经可用。

## 三步调用：直接复制

### 1．上传 PPT，在规划聊天发送

```text
用 $teach-1-plan 分析这份PPT。
给出教学图拆分方案、每图标题、原页覆盖映射和逐图完整版提示词。
先不生图；规划完成后统一让我确认，并询问保存文件夹名称。
```

确认数量、标题、拆分/合并、保留项及内容冲突。没有输入 PPT 时等待上传，不自动使用项目旧文件。

### 2．确认规划，在同一聊天发送

将方括号占位内容替换为实际名称和输出方式：

若暂时只生图，可将下面的“复现阶段”一行改为“本次先不复现，保存好资料，以后在新聊天逐图复现”，不必现在决定合并方式。

```text
确认这套规划，文件夹名称为“[填写文件夹名称]”。
用 $teach-2-gen 按确认提示词生成全部教学图。
保存到生图子项目，同时保存规划、完整提示词、复现清单和复现交接.md。
复现阶段[合并为一个PPTX／每张图分别输出PPTX]。
交接文件要能让新聊天独立执行。
我确认最终图片版本后，请给我一段填好真实绝对路径的 $teach-3-ppt 调用语句，方便复制到新聊天。
```

逐图核对中文、代码、公式、数据、真假分支和循环。修正并选定最终图片版本后，再把它交给复现聊天。

默认教学主体目标为 1814×867、白底、无总标题栏、大字号；实际工具输出尺寸如实记录，不能裁切或拉伸冒充达标。图片文件名使用确认标题。

### 3．可选：在同项目新聊天逐图复现

复制第二阶段给出的、已填好真实路径的调用语句。手动填写时使用：

```text
用 $teach-3-ppt 执行这套复现任务。

交接文件：[填写复现交接.md的绝对路径]

先读取适用项目规则和交接文件，再核对原图、复现清单及模板。
忠实复刻每张确定版本原图，每张图分别输出一个与原图同标题的对象级可编辑PPTX。
输出到复现子项目，交付PPTX、页面预览和验证报告。
以本次任务包为依据，无需读取规划聊天历史。
```

新聊天必须能访问交接文件及其引用的原图、清单、素材和模板。换电脑时迁移完整任务包并修正路径，不能只复制一份交接文件。无需复制旧聊天记录或去 GitHub 重贴整个 SKILL.md。

这一步可以现在做、以后做或不做。需要合并时将调用中的“分别输出”改为“按交接顺序合并为一个PPTX”，并提供合并文件名。只有用户启动复现任务后，才建立对应复现任务目录。

## 任务与模块命名规则

这里的“模块”指规划中确认的一张教学图；同一张图内的卡片或知识小节不是新的子项目。

| 对象 | 命名规则 | 示例 |
|---|---|---|
| 新主题项目文件夹 | 用户按教学主题命名 | 按键控制教学图 |
| 生图任务文件夹 | 规划确认时询问并使用用户答复 | 生图/独立按键入门 |
| 每张图的标题 | 规划阶段按核心主题拟定，用户确认；标题保存在规划与清单，默认不画入主体图 | 按键消抖原理 |
| 图片文件 | 确认标题＋实际格式扩展名，不擅加编号或改名 | 按键消抖原理.png |
| 顺序编号 | 规划和交接中保存编号及来源页映射，排序不依赖文件名 | 第2图，对应PPT第4～5页 |
| 单图完整提示词 | 标题＋固定用途后缀，与原图对应 | 按键消抖原理-提示词.md |
| 单图准确复现清单 | 标题＋固定用途后缀，与原图对应 | 按键消抖原理-复现清单.md |
| 整套任务资料 | 使用固定功能名，不逐模块新增README/项目交接 | 生图规划.md、生成记录.md、复现交接.md |
| 独立参考素材 | 按图标题及素材用途清楚命名，保留来源；已有用户文件可保留原名并登记对应关系 | 按键消抖原理-波形参考.png |
| 分别复现的文件 | 与原图同标题＋.pptx | 复现/独立按键入门/按键消抖原理.pptx |

同名标题、Windows非法字符、已有文件冲突或版本返工，先给出可用名称让用户确认，不覆盖旧成品。规划、提示词、图片和清单的对应关系同步更新。返工保留旧版本，并在交接中只指定最终选定版本。

## 任务目录与交接

你的教学主题项目可按如下边界组织，按真实需要创建文件，不预建空目录：

```text
教学主题项目/
├── AGENTS.md                    主题项目共用规则
├── 生图/
│   ├── README.md、项目交接.md
│   └── 用户命名的任务文件夹/
│       ├── 规划、完整提示词、原始输入
│       ├── 按确认标题命名的图片
│       ├── 复现清单及必要独立素材
│       └── 复现交接.md
└── 复现/                        启动可选复现任务后才创建
    ├── README.md、项目交接.md
    └── 本次复现任务/
        └── PPTX、页面预览、运行进度及验证报告
```

“所有项目集合目录”不是主题项目，不自动创建 AGENTS。普通素材/脚本目录不是业务子项目，不自动添加 README 或交接。复现可读取确定版本原图，输出只写复现任务目录，不覆盖上游原图。

复现交接至少包含：按顺序排列的图标题、最终原图路径和版本、真实尺寸、完整提示词路径、准确文字/代码/公式与连接关系清单、独立素材位置、模板及主体区域、合并/分别输出选择、输出目录、已知问题和验收要求。清单与原图实质冲突时先明确处理。

## 本仓库结构与维护

本仓库是可安装的公开发布包，不是教学素材存储库：

```text
.agents/skills/teach-1-plan/       规划技能及显示信息
.agents/skills/teach-2-gen/        生图技能、显示信息、完整生图规范
.agents/skills/teach-3-ppt/        复刻技能及显示信息
scripts/sync-skills.cjs           从维护原件同步发布包
README.md                        安装和复制调用的唯一说明入口
AGENTS.md、项目交接.md            仓库维护规则与实际状态
LICENSE                          MIT
```

初版来自维护者的 [提示词系列仓库](https://github.com/zcq19991029/codex-prompt-series) 中同名技能。当前维护原件仍在该仓库 `.agents/skills/`，本仓库按版本同步发布，禁止两边独立修改同一技能。维护者使用 Node.js：

```bash
node scripts/sync-skills.cjs /绝对路径/提示词系列/.agents/skills
```

该脚本只同步三个指定技能的发布文件，不安装用户技能、不修改本机链接。普通使用者直接安装本发布仓库即可。更新本发布仓库前核对 diff、完整引用和技能校验结果。

本包无应用启动、构建或网站部署步骤；发布方式为 Git 提交并推送到公开 GitHub 仓库。维护者修改运行说明时更新 README，进度和验证变化更新项目交接。用户资料、生成图片、OCR Token 和登录状态不进入本公开包。

## 验证与当前限制

当前版本为 0.1.0。三个技能通过 quick_validate；全部7个技能资源与维护原件一致，跨技能相对引用有效。已公开发布，并使用官方安装器从本仓库 main 分支完成隔离安装，核对安装资源与发布文件一致；没有覆盖维护者原有安装入口。详细结果在项目交接中记录。

尚未用本发布包完成一套真实教学 PPT 的规划、生图和复现闭环；没有示例成品可作为效果承诺。尺寸、文字准确性、外部服务和最终 PPT 可编辑性需要按每次任务实际验收。结构检查和可见渲染分别记录，未验证项不能写成已完成。
