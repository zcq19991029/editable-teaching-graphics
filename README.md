# 可编辑教学图

给教师使用的 Codex 四阶段技能包：**教学 PPT 拆解规划 → AI 教学主体图 → 模板嵌图合成 → 在独立聊天中复刻为可编辑 PPTX**。

四个技能有固定顺序和简短名称，安装后复制下方调用语句即可。先新建一个空文件夹作为教学主题项目：一个聊天完成规划、确认和生图；另一个聊天按需复刻每张图。第三、四阶段可暂时不做，前两阶段仍保存好后续复现资料。

| 顺序 | 技能 | 输入 | 交付 |
|---|---|---|---|
| 1 | `$teach-1-plan` | 教学 PPT/PPTX、保留项 | 拆图数量、标题、原页覆盖映射、逐图完整提示词 |
| 2 | `$teach-2-gen` | 确认后的规划、用户命名的文件夹 | 教学图、准确复现清单、生成记录、复现交接.md |
| 3 | `$teach-3-embed` | 确定版本图片、索引、PPT模板 | 展示版PPTX，检查结论并入生成记录 |
| 4 | `$teach-4-ppt` | 确定版本原图、清单、可选模板 | 对象级可编辑 PPTX、页面预览、验证报告 |

图片生成阶段交付的是位图。复刻后普通文字、代码、卡片、表格和连接线应成为相应原生对象；复杂插图可保留为独立图片，交付报告须说明编辑范围及差异。

## 第三阶段：模板嵌图合成

生图完成后可在同一聊天调用 `$teach-3-embed`。模板合成按已确认顺序匹配标题和图片，保留模板装饰，完整等比放图、底端对齐并保护横线。标题可编辑，图内内容仍为图片。对象级可编辑复刻顺延为第四阶段 `$teach-4-ppt`，按需在新聊天执行。

```text
用 $teach-3-embed 合成这套确定版本教学图。
模板：[填写模板路径；未指定时检查生图工作区的嵌图模板.pptx]
图片与顺序：[填写图片任务文件夹或索引路径]
每图一页，填写对应标题；图片等比、底端对齐，上端在模板横线下方且不遮挡横线。
PPTX保存在同一个图片任务文件夹内，检查结论并入生成记录；临时预览检查后清理，保留原图与模板。
```

默认共享模板为“生图/嵌图模板.pptx”；输出为“生图/用户命名任务文件夹/任务名-嵌图版.pptx”。比例造成的小间隙如实记录，不裁切、拉伸或假称完全贴齐。页数由确定版图片清单决定。

## PPT参考、原创插图与当前提示词

PPT提供教学依据，生图阶段默认重新设计教学表达，不要求外观相似。参考图片分为内容依据、对象外观参考、风格参考、用户明确指定原样保留的复用素材；只有最后一类必须忠实复用。普通原图可以重绘或替换成原创设备、情境、流程或视觉比喻，原页没有插图也应正常生成，不必等待素材。

创新范围包括构图、插图、主题内解释、通俗改写和视觉叙事；评分数字、代码、公式、技术条件和逻辑关系保持准确。版式与颜色建议留有空间，不强制每张都用彩色卡片。生成设备和作品是示意，不冒充真实学生成果。只有第四阶段teach-4-ppt才忠实复刻已经确定的教学图。

每图当前完整提示词集中放在任务目录的提示词/标题-提示词.md，本地只保留一个当前文件，不默认生成历史版本或备份目录。修订更新当前文件和索引，生成记录保留实际提交版本及SHA-256。用户授权清理后，只删除确认属于旧提示词的文件；原PPT、参考素材、图片成品和运行记录不随之清理。

## 从空文件夹开始：两个聊天怎么用

1. 在自己的项目集合目录下，新建一个用教学主题命名的空文件夹，例如“按键控制教学图”，在 Codex 中将它打开为项目。已有个人级技能安装可直接使用；否则先按下文安装或建立项目技能链接。教学任务材料放这个新项目内，不放本技能发布仓库。
2. 在这个项目的第一个聊天上传 PPT，先只看建议图数量、标题、拆分理由与内容覆盖说明，确认要不要增减。PPT页数与图数量分别报告，不要求一页对应一图；此时不编写逐图长提示词。
3. 确认数量方案并回答任务文件夹名称后，才编写完整提示词，逐图保存为本地文件并建立索引。检查后回复“生成”，同一聊天再调用 teach-2-gen，逐张读取对应文件、生成、保存和核对，再处理下一张。无需重复批准已授权的每张图。
4. 确认最终图片版本后，可以就此结束，也可以以后在这个项目中另开一个聊天，读取复现交接，逐图复刻。默认每张图输出一个同名 PPTX；需要时也可以明确要求合并。只生图时不自动启动复现或创建空复现任务目录。

第一个聊天的启动语句（替换路径后直接复制）：

```text
这是一个新的教学图项目，项目目录是：[填写新建空文件夹的绝对路径]。
请将本次输入、规划、提示词、图片和交接资料都保存在这个项目内。
按实际需要建立生图工作区和项目说明，不预建空复现目录或为每个素材文件夹创建README。

先用 $teach-1-plan 分析我上传的PPT，报告实际PPT页数和检查范围，
先只规划应拆成多少张教学图，给出逐图标题、拆分理由和来源页映射。
此时不要编写完整版提示词；请让我确认数量和增减，并询问任务文件夹名称。

收到数量方案确认和文件夹命名答复后，再编写逐图完整提示词，
以UTF-8保存为“标题-提示词.md”，保存生图规划.md和提示词索引.md，并回读核对。
提示词保存后仍先不生图，等我回复“生成”再继续用 $teach-2-gen。
按确认顺序每次读取一张图的完整提示词及参考素材，传入生图工具，保存检查后再处理下一张。
不要凭聊天记忆重新写一套提示词，也不要用摘要替代完整文件正文。
图片按确认的逐图标题命名，保存到本项目生图工作区的用户命名文件夹。
同时保存规划、完整提示词、准确复现清单及复现交接.md。
本次不自动复现；复现是可选的后续任务。
我确认最终图片版本后，请提供填好真实路径的、新聊天逐图复现调用语句。
```

数量方案确认与生图授权是两个步骤：先确认增减，再落盘完整提示词，最后等待生成回复。只有用户另行明确授权自动生成时才省去最后一次等待。即使暂时不复现，也保留确定版本原图、完整提示词、准确文字/代码/公式、连接关系、独立素材及已知问题，方便以后继续。

## 技能引用为什么显示成中文标签

Codex 可能把输入框中的技能引用显示为带图标的中文标签，例如“1 教学图规划”；它对应技能显示名，实际调用名仍是 `teach-1-plan`。在仓库复制下方代码块里的纯文本即可，`$teach-1-plan`、`$teach-2-gen`、`$teach-3-embed`、`$teach-4-ppt` 不需要复制图标或截图，也不需要把每个 SKILL.md 全文粘进聊天。技能须已安装且能被当前项目发现。

## 安装

### 方法一：让 Codex 安装（推荐）

在具备 `skill-installer` 的 Codex 中复制：

```text
用 $skill-installer 从公开仓库 zcq19991029/editable-teaching-graphics 的 main 分支安装以下四个技能：
.agents/skills/teach-1-plan
.agents/skills/teach-2-gen
.agents/skills/teach-3-embed
.agents/skills/teach-4-ppt

四个技能必须同时安装并保留全部 references 和 agents 文件。
如果已经存在同名技能，先核对原件和链接；不要直接覆盖或创建重复入口。
安装后检查四个技能名称及相对引用，并报告实际安装位置。
```

安装后在下一条消息调用技能；若没有出现，重开聊天或重启 Codex。当前安装器默认安装到 `$CODEX_HOME/skills`（未设置时为 `~/.codex/skills`）；安装器路径与用户级 `.agents/skills` 发现路径应按实际环境核对。

### 方法二：在项目中使用

有 Git 时执行：

```bash
git clone https://github.com/zcq19991029/editable-teaching-graphics.git
cd editable-teaching-graphics
```

在这个目录打开 Codex，技能原件位于本仓库 `.agents/skills/`。要在自己的教学项目中使用，可让 Codex将项目 `.agents/skills/teach-*` 或用户 `~/.agents/skills/teach-*` 目录链接到这四个完整技能文件夹。Windows 使用 Junction，macOS/Linux 使用符号链接；不要使用 `.lnk` 文件。已有同名入口时先核对，换电脑重新建立链接。不要在仓库和用户目录重复安装同名副本。

安装与目录发现规则参考 [Codex 官方技能文档](https://developers.openai.com/codex/skills/)。

## 外部依赖

本仓库只提供教学工作流技能，不捆绑模型服务、OCR 凭据、PPT 模板或第三方工具实现。

- **规划**：需要当前环境中适用的 PPT 读取与渲染能力，例如已安装的 `presentations` 或 `officecli-pptx`。只读标题不能代替检查实际页面。
- **可选OCR辅助**：原生文字优先直接提取；对截图/扫描页里的代码、公式和标注可复用已配置PaddleOCR-VL及image-to-editable-ppt的text_hints思路，识别结果要与原图交叉核对，不能把离线几何检测当准确文字识别。生成图也可按需OCR对照清单，再视觉检查流程与素材。只借鉴识别能力，不自动启动复刻流程；详见技能内references/input-ocr.md。缺少OCR不强制阻塞正常可读PPT，关键内容无法读清则标注并解决，不能猜改。
- **生图**：需要当前环境可用的 `imagegen` 技能及实际生图工具。安装本包不会自动开通生图能力，也不固定宣称某个型号是“最新模型”。
- **模板合成**：需要PPT读写和渲染能力，例如 officecli-pptx；读取真实模板，不捆绑个人模板。
- **复现**：必须另装 [image-to-editable-ppt](https://github.com/ningzimu/image-to-editable-ppt-skill)，并按其安装说明准备 `editppt` CLI。该技能是独立上游依赖，不复制进本仓库。

复现依赖可复制此段让 Codex 安装和诊断：

```text
用 $skill-installer 从 ningzimu/image-to-editable-ppt-skill 的 main 分支安装 skills/image-to-editable-ppt。
已安装时先核对版本和入口，不覆盖我的配置。
然后读取该技能及其 references/cli-helper.md，按当前安装说明检查或安装 editppt CLI，运行 editppt --help 和 editppt doctor，报告可用性及缺失依赖。
不要把仅安装技能文件写成复现环境已通过。
```

多页复现按上游要求使用 page worker，需要支持子代理的环境；不支持时报告限制。OCR 与图像后台是否可用由该依赖运行时诊断，不把本包安装成功当作这些服务已经可用。

## 四步调用：直接复制

### 1．上传 PPT，在规划聊天发送

```text
用 $teach-1-plan 分析这份PPT。
先只给建议教学图数量、每图标题、拆分理由和原页覆盖映射。
先不编写完整提示词，也不生图；让我确认图数量是否需要增减，并询问任务文件夹名称。
```

确认数量、标题、拆分/合并、保留项及内容冲突。没有输入 PPT 时等待上传，不自动使用项目旧文件。

### 2．确认数量后编写提示词，再回复生成

先确认数量方案，让提示词落盘：

```text
确认这套图数量和拆分方案，文件夹名称为“[填写文件夹名称]”。
继续用 $teach-1-plan 编写逐图完整提示词，以UTF-8保存为“标题-提示词.md”。
保存生图规划.md和提示词索引.md，回读核对后给我文件路径与概览。
此时先不生图，等待我的生成回复。
```

提示词给出并保存后，确认生成范围，再发送：

若暂时只生图，可将下面的“复现阶段”一行改为“本次先不复现，保存好资料，以后在新聊天逐图复现”，不必现在决定合并方式。

```text
生成。用 $teach-2-gen 按提示词索引生成全部已确认教学图。
每次读取当前图完整提示词文件及参考素材，使用完整正文调用生图工具。
当前图保存和检查后再读取下一图；不要用聊天摘要重新编写提示词。
记录提示词路径、版本、SHA-256、实际模型标识、图片路径和检查结果。
保存到生图子项目，同时保存规划、完整提示词、复现清单和复现交接.md。
复现阶段[合并为一个PPTX／每张图分别输出PPTX]。
交接文件要能让新聊天独立执行。
我确认最终图片版本后，请给我一段填好真实绝对路径的 $teach-4-ppt 调用语句，方便复制到新聊天。
```

逐图核对中文、代码、公式、数据、真假分支和循环。修正并选定最终图片版本后，再把它交给复现聊天。

默认教学主体目标为 1814×867、白底、无总标题栏、大字号；实际工具输出尺寸如实记录，不能裁切或拉伸冒充达标。图片文件名使用确认标题。

本地文件可减少长对话中遗漏或改写要求的风险，逐张读取可核对每张图实际使用的输入；不能保证图像模型每次严格画对文字、公式或流程，所以生成后仍需检查。完整提示词默认写文件、聊天给索引与概览；用户要求全文时再展开，避免聊天重复输出整套长文本。

默认使用执行当时最新可用的OpenAI/ChatGPT生图模型，不固定2.5、3或4。生成前依据官方文档和工具实际能力说明“官方最新系列／当前实际可用型号／拟使用型号／核对日期”；能选择时使用最新可用版本。官方已发布与当前工具可调用分别核对，不能只靠版本号猜测。

模型名称以执行时官方文档和工具实际可用性核实，不保留固定版本示例。内置工具未暴露底层型号时如实注明“版本未核实”；无法满足最新模型要求时说明限制，等用户选择可用方案，不静默降级或自行改用收费API。

### 3．可选：在生图聊天合成模板展示版

```text
用 $teach-3-embed 合成确定版本教学图。
任务目录：[图片所在任务文件夹的绝对路径]
顺序与标题：[提示词索引.md的绝对路径]
模板：[嵌图模板.pptx绝对路径]
输出：[任务目录内的展示版PPTX绝对路径]
每图一页，图片等比、底端对齐，保护模板横线和页眉；标题匹配索引。
检查全部页面后将结论写入生成记录，清理本次临时预览和制作文件。
保留原图、模板及已有成品。
```

此步需用户授权，可跳过并直接用确定PNG执行第四阶段；“生成图片”本身不授权合成PPT或复刻。

### 4．可选：在同项目新聊天逐图复现

复制第二阶段给出的、已填好真实路径的调用语句。手动填写时使用：

```text
用 $teach-4-ppt 忠实复刻这套确定版本教学图，制作对象级可编辑PPT。

项目根目录：[绝对路径]
复现交接文件：[复现交接.md的绝对路径]
总索引：[提示词索引.md的绝对路径]
原图目录：[图片目录的绝对路径]
逐图复现清单目录：[复现清单目录的绝对路径]
必要独立素材：[目录路径；没有则填“无”，不得凭空补素材]
模板：[PPT模板绝对路径；没有则填“无”，按原图比例]
已有嵌图展示版：[PPT路径；没有则填“无”，仅供标题及排版参考]
生成与检查记录：[生成记录.md的绝对路径]
复刻范围：[全部／索引中的指定编号]
输出形式：[每图分别输出／按索引顺序合并为一个PPTX]
输出目录：[复现子项目下的任务目录绝对路径]
合并文件名：[选择合并时填写；分别输出则使用各图确认标题]

先核对项目规则、输入文件及索引中标题与图片、提示词、清单的对应。
以最终原图为布局和插图依据，以复现清单校对准确文字、数字和关系。
普通文字、代码、表格、卡片及连线重建为原生对象，复杂插图可忠实分离为独立图片。
保留原图比例，按模板主体区放置；禁止整图铺底覆盖文字的伪可编辑。
输出仅写指定复现目录，保留生图原图和已有展示版。
按公共image-to-editable-ppt技能完成验收，交付PPT及必要验证材料，说明编辑范围和差异。
若显式填写的路径或输出选择与交接冲突，先指出并解决；不得静默改选。
无需读取规划聊天历史。
```

新聊天必须能访问交接文件及其引用的原图、清单、素材和模板。换电脑时迁移完整任务包并修正路径，不能只复制一份交接文件。无需复制旧聊天记录或去 GitHub 重贴整个 SKILL.md。

这一步可以现在做、以后做或不做。填写输出形式，选择合并时同时提供合并文件名。只有用户启动复现任务后，才建立对应复现任务目录。

## 任务与模块命名规则

这里的“模块”指规划中确认的一张教学图；同一张图内的卡片或知识小节不是新的子项目。

| 对象 | 命名规则 | 示例 |
|---|---|---|
| 新主题项目文件夹 | 用户按教学主题命名 | 按键控制教学图 |
| 生图任务文件夹 | 规划确认时询问并使用用户答复 | 生图/独立按键入门 |
| 每张图的标题 | 规划阶段按核心主题拟定，用户确认；标题保存在规划与清单，默认不画入主体图 | 按键消抖原理 |
| 图片文件 | 确认输出页序号＋标题＋实际扩展名 | P01-按键消抖原理.png |
| 顺序编号 | 索引分别记录来源页、图编号及输出页序号，视频页保留占位 | 第2图，对应PPT第4～5页 |
| 单图完整提示词 | 标题＋固定用途后缀，与原图对应 | 按键消抖原理-提示词.md |
| 单图准确复现清单 | 标题＋固定用途后缀，与原图对应 | 按键消抖原理-复现清单.md |
| 整套任务资料 | 使用固定功能名；索引记录顺序、标题和提示词路径，生成记录绑定实际调用版本 | 生图规划.md、提示词索引.md、生成记录.md、复现交接.md |
| 独立参考素材 | 按图标题及素材用途清楚命名，保留来源；已有用户文件可保留原名并登记对应关系 | 按键消抖原理-波形参考.png |
| 分别复现的文件 | 与原图同标题＋.pptx | 复现/独立按键入门/按键消抖原理.pptx |

同名标题、Windows非法字符、已有文件冲突或版本返工，先给出可用名称让用户确认，不覆盖旧成品。规划、提示词、图片和清单的对应关系同步更新。图片成品返工保留旧成品，并在交接中指定选定版本；提示词每图仅保留一个当前文件，修订记录写入索引和生成记录，已有旧提示词按用户授权清理。

你的教学主题项目可按如下边界组织，按真实需要创建文件，不预建空目录：

│       ├── 输入/                 原始PPT
│       ├── 参考素材/             确有需要的来源资料和独立素材
│       ├── 提示词/               标题-提示词.md，每图一个当前文件
│       ├── 图片/                 标题.png，保存确定版本
│       ├── 复现清单/             标题-复现清单.md，准确内容及关系

│       ├── 提示词索引.md          唯一总表：顺序、标题、路径、尺寸、哈希
│       ├── 生成记录.md            生成、修订及嵌图检查结论
│       ├── 复现交接.md            引用总索引，补充模板及复刻约束

“所有项目集合目录”不是主题项目，不自动创建 AGENTS。普通素材/脚本目录不是业务子项目，不自动添加 README 或交接。复现可读取确定版本原图，输出只写复现任务目录，不覆盖上游原图。

## 版本与升级注意
索引区分当前提示词哈希和实际生图提交哈希，同时锁定选定图片SHA-256及核对状态；模型修订、图片返工或共享模板更新不会自动同步已有PPT，记录中标记受影响产物待更新，重做时另存并重新验收。原图、准确内容与清单有冲突时先解决，不能由复刻阶段静默纠错。
从旧三阶段包升级时，teach-3-ppt已迁移为teach-4-ppt，teach-3-embed是新第三阶段。先核对旧入口来源和本机自定义内容，再按升级授权迁移或移除旧发现入口；不能同时保留两个冲突复刻入口，也不能删除目录链接的后端原件。安装新技能后检查四个调用名和依赖，发现成功与运行成功分别记录。

## 视频页与页序号
读取PPT时同时检查逐页媒体对象、OOXML视频/媒体关系及外部链接，结合页面渲染和文件类型判断。嵌入视频可据媒体关系识别，外链或在线播放器记录其链接与识别依据；单独封面图、播放按钮或失效链接只能标“疑似视频，待核对”，不能承诺一定识别或已验证可播放。不播放、不转录、不下载、不提取视频帧，也不读取视频内容补教学图。
已确认视频页按用户约定整页跳过，即使同页含文字也不擅自拆图；在规划与唯一总索引保留该页的来源页码和输出页序号，类型为“视频占位”，状态为“跳过生图”，图片/提示词/复现清单路径均记“—”。疑似页面先报告并解决，不静默遗漏。源PPT及其中视频保持原样。
规划先确定完整输出页序列：普通教学图页和视频占位页共同占页号；图片数量与最终PPT页数分别报告。允许拆分/跨页合并时分别记录来源PPT页码、教学图编号和输出页序号，三者不得混淆。视频占位在原教学顺序位置保留，后续不能因为没有图片而压缩该页号。
新任务文件统一用“P01-确认标题.png”“P01-确认标题-提示词.md”“P01-确认标题-复现清单.md”，P01指确认后的输出页序号；必要时扩为三位补零。主体图不画总标题或页码。索引绑定前缀、标题与来源页，视频页没有空提示词文件或占位PNG。页序调整同步所有关联路径并标旧PPT待更新，不能按目录排序猜顺序。
第三阶段根据完整页序合成：图页放图，视频页只留下模板空主体区域及页号，不插图、不插视频、不自动写内容标题；记录视频未迁入，待用户自行补入。第四阶段只派发有原图的图页给公共复刻技能，完成后按完整页序组装并插入空白视频占位页，复核页数与页号；不能将空占位页送去OCR或图像重建。仅逐图分别输出时不制造空PPT文件，视频页位置保留在总索引与交接。
旧任务已有无编号文件不自动批量改名；沿用索引中已确定路径，用户明确要求迁移时才统一改名并更新引用。
