# 按需OCR辅助教学内容核对

用途：辅助提取PPT内截图、扫描教材、代码图、公式图及设备标注；也可辅助核对生成图片。OCR只提供识别证据，不能决定拆图数量、教学逻辑或正确答案。

1. PPT原生文字、备注、表格和代码优先直接提取，再结合实际页面渲染。只对图片中的关键内容、提取冲突或疑似遗漏区域按需OCR；原生文本可读时不强制整套调用外部服务。
2. 输入来源保持独立：原生提取、OCR文本、视觉核对分别记录页码、区域和出处。对=与==、端口/型号、括号、十六进制、单位、上下标等逐项看原图；OCR不确定或三者冲突时标注待确认，不猜改。
3. 复用已配置的OCR服务及现有公共工具，不复制上游后端。可参考已安装image-to-editable-ppt的SKILL.md、references/cli-helper.md中PaddleOCR-VL及text_hints流程，先查看当前editppt doctor和相关命令帮助。需要时把选定图片作为独立page目录的source.png，用当前支持的editppt page hints取得text_hints.json/png；只有检查命令实际输入要求后执行。不为规划自动开启整套prepare/dispatch/record/finalize复刻流程。
4. 上游离线检测主要是文字几何定位，不能当作已识别出准确内容。缺少服务/Token时如实说明，继续可用的原生提取和视觉核对；若关键内容无法读清，停止受影响条目的完整提示词编写并请求清晰输入。需要用户选择是否启用服务时一次说明用途，不重复催问。凭据在已有工具配置中管理，不写任务包、日志或公开仓库。
5. 仅处理本次任务必要页面或裁图。外部OCR使用须符合用户已授权范围及本地/保密约束；上游复刻请求的授权不自动等同于规划请求的外部上传授权。已配置且用户已授权的服务不重复索要许可。
6. 按需保存OCR原始输出和核对记录于任务目录，提示词只能使用已核对的准确内容。图数量方案确认后再融合到完整提示词，OCR不能绕过数量确认。
7. 生成后可按需OCR核对重点文字、代码和公式，与已确认清单比较；同时视觉检查连线、真假分支、回路、布局和素材身份。OCR相似度高不等于技术正确或图片合格。记录通过/冲突/不可读/未验证；只修复受影响图。

示例：PPT中第6页是一张C51代码截图，原生提取为空；仅对代码区域做OCR并逐符号看原图，记录变量和运算符后用于确认后的提示词。可正常提取的其余页不因这个案例强制整套OCR。

验证：可追溯来源；关键符号已看原图；离线几何定位与服务识别明确区分；未读清内容没有冒充准确提取。本参考不承诺OCR免费额度或服务始终可用。
