# 完整教学主体图规范

初版来源：原“08-通用教学信息图与可编辑PPT复现”提示词的生图要求。当前完整规范维护于本文件，不依赖旧复制版 MD；本技能不自动查询线上替换已确认任务规范。

生成一张 1814×867 像素的中文横版教学信息图，用于直接插入 PPT 标题下方的空白区域，并便于以后重建成对象级可编辑的 PowerPoint。

【模型与执行】
使用执行当时最新可用的OpenAI/ChatGPT生图模型，不固定2.5、3或4。先核对官方当前文档与实际工具能力，告知官方最新系列、当前可用型号、拟使用型号及核对日期。内置工具优先；不暴露版本时注明未核实，无法满足最新要求时说明限制并等待选择，不静默降级或自行切换收费API。整套任务先确认图数量，再保存逐图完整提示词；用户回复生成后，每次读取一图完整文件及参考素材，按完整正文生成，保存检查后再读下一图。每图本地仅保留提示词/标题-提示词.md一个当前文件，不默认保存历史提示词副本；修订更新索引并记录原因及旧/新哈希。记录当前文件与实际提交正文各自的版本/SHA-256，已提交请求绑定当时哈希，输入一致不代替图片验收。

【统一要求】

1. 精确适配 1814×867 像素横版比例。若工具不支持精确尺寸，保持目标比例和完整内容，报告实际尺寸，不宣称精确达标，不裁切、不变形。
2. 默认只生成 1 张图片，不要一次生成多个版本。
3. 不要任何总标题栏，不要课程名称，不重复 PPT 已有标题。
4. 图片顶部直接开始教学主体，四周只留约 20～30 像素安全边距。
5. 不生成 PPT 整页，只生成标题下方的教学主体区域。
6. 白色背景，整体清晰、现代、简洁，适合职业院校课堂、希沃白板和 16:9 PPT 使用。
7. 使用蓝、绿、橙、紫、红等颜色区分不同知识模块，不使用大面积深色背景。
8. 可以使用圆角卡片、编号、箭头、流程图、表格、代码框、虚线框、对照框、提示框、二进制格子帮助理解。
9. 不要学校Logo、水印、校徽、无关人物、装饰性卡通或复杂科技背景。与教学含义直接相关的动作、工具、场景或人物示意可以原创，不能让装饰挤占知识表达。
10. 中文字体必须足够大，插入 PPT 后仍然清晰，避免大量小字和长段文字。
11. 重要知识点、代码、数值和关键词可以使用颜色突出。
12. 面向初学者，优先使用通俗、人话式解释，但不能为了通俗而产生技术错误。
13. 根据教学主题自主选择叙事和布局；概念、原理、示例、过程、对比或总结均为可选表达，不把所有页面强行套成同一教学顺序或卡片模板。
14. 用户提供多张教材截图、PPT 截图、代码图或其他参考图片时，先理解素材关系，再重新整理为一张信息图，不简单拼图。
15. PPT与上传图片作为教学内容和对象参考，不是外观复刻模板。默认重新构图、原创插图和视觉表达，不要求保留原页布局或图片；只有用户明确指定原样保留的素材才忠实复用。没有插图的主题也应生成帮助理解的原创视觉。
16. 用户说“内容不变”时保留知识含义与关键条件，普通讲解可以通俗改写、提炼和图示化；只有明确要求逐字保留的题干、代码、数据、公式或指定文字才按原文，不自动把整页文字锁成逐字照抄。
17. 不增加无关知识点或编造事实；允许围绕本图主题进行通俗改写、视觉比喻、原创设备示意和必要解释性图示。创新表达不能改变数字、技术含义、条件和关系，不将生成示意冒充真实成果证据。
18. 内容较多时优先提炼和重组，不缩小字号硬塞；不得删掉用户要求保留的代码、数据或关键条件。
19. 确实无法一张清楚呈现时优先保证主要内容，不擅自生成第二张；在图外说明无法容纳的内容，不隐瞒遗漏。

【代码与技术内容要求——仅在本页涉及相关内容时启用】

20. 所有 C 语言、C51、单片机代码，以及其他学科的公式、数据和符号必须准确；不要把通用教学内容自动转换成编程主题。
21. 代码尽量使用等宽字体。
22. 不修改用户提供的变量名、函数名、端口名、型号、数值、十六进制数据和程序逻辑。
23. 严格区分 ( ) 圆括号、{ } 花括号、[ ] 方括号。
24. 严格区分 = 与 ==、& 与 &&、| 与 ||、: 与 ;、++ 与 +、-- 与 -。
25. 十六进制、十进制、二进制之间的对应关系必须正确。
26. 流程图箭头方向、执行顺序、真假分支、循环回路与实际代码或学科原理一致。
27. “真/假”“是/否”标在正确分支。
28. 循环结构必须画出返回条件重新判断的箭头，不漏回路。
29. 多分支结构表现真实判断顺序，不为美观改变执行逻辑。
30. 代码、公式与电路关键关系以实际内容为基础，不换成另一套逻辑；外观、插图和解释方式可以重新设计。概念性设备示意不必复制原照片，不能凭空补写实际端子、型号或接线。
31. 素材存在明显不一致时，不猜测改动；按用户明确说明处理，无法确认的实质冲突先指出。

【教学表达要求】

32. 一页只解决一个核心主题。
33. 模块职责清晰，不重复讲同一句话。
34. 能用流程图、箭头、对照图表达时少写长段文字。
35. 能用代码直接说明时，不只写抽象定义。
36. 可以设置“人话理解”“重点”“注意”“易错点”。
37. 适合时在底部加“本页记住3～5句话”的总结条，内容较满时可省略。
38. 根据知识选择适合的空间结构，单栏、双栏、三栏、上下结构只是示例；提示词建议布局可调整，主题关系与必要内容准确即可，不限制原创插图和构图。
39. 代码型内容优先“代码 + 箭头标注 + 执行流程”。
40. 对比型内容优先左右对照。
41. 分类型内容可使用分区、对象集合、场景、对照或颜色等表达；不强制彩色卡片，避免所有图只换文字而版式相同。
42. 二进制、位运算、端口状态优先 0/1 格子和方向箭头。
43. 综合程序题体现变量值逐步变化，不只给最终答案。

【便于后续可编辑 PPT 重建的视觉规范】

44. 主体画布纯白#FFFFFF，信息布局底板与连线优先纯色、清楚分离。设备或情境插图可按教学需要采用写实、扁平或示意风格，允许必要体积与材质；不把便于重建的布局约束机械套到所有插图，不使用干扰阅读的复杂背景或效果。
45. 默认正文 #1F2937；蓝 #2563EB、绿 #16A34A、橙 #EA580C、紫 #7C3AED、红 #DC2626；浅底 #F8FAFC；边框 #CBD5E1。同类模块用同色，颜色含义保持一致。
46. 中文使用清晰无衬线字体（思源黑体/微软雅黑风格），代码用 Consolas 风格。保持少量统一字号层级，文字水平排列，不弯曲、不倾斜、不转成艺术字。建议模块标题约 36～44 px、正文 28～34 px、代码 30～36 px，按实际内容调整，保证课堂可读性。
47. 将文字、卡片底板、连线、编号和插图作为视觉上可分辨的对象设计。文字不要跨多个卡片、压在箭头上或融入复杂插图；标签尽量放在插图外部，并用清晰引线连接。
48. 布局图形采用标准矩形、圆角矩形、菱形、圆形、直线及折线连接符；同类图形统一圆角和线宽，通常线宽 2～3 px。不要用手绘笔刷或复杂异形图案表示普通布局结构。
49. 连线端点明确落在对应节点边界，标签与连线分离；交叉线清楚区分，不用色彩或装饰掩盖拓扑关系。流程回路和分支不得为降低重建难度而删除。
50. 表格使用规则行列、明确边界、单元格内独立文字，避免不必要的合并单元格。0/1 格子等宽等高，对齐位编号和对应数值。
51. 主动生成有助于理解的原创设备、情境或原理示意；原页没有插图不构成缺少素材，也不阻止生成。参考图标明角色：教学内容依据、对象外观参考、风格参考或用户明确锁定的复用素材；前几类不要求照搬，只有最后一类须忠实复用。插图完整、边界清晰，与文字保留约16～24px间隔。设备示意不得猜造具体端子/接线，生成作品不得冒充真实成果证据。
52. 图片中公式必须准确完整，图外保留可用于后续重建的公式原文或 LaTeX，不以图片公式冒充可编辑公式。
53. 若当前工具支持文本输出，在图片之外附一份简短“复现清单”：逐模块准确文字、代码原文、公式原文、节点连接关系（含真假分支）、颜色与字体层级、独立插图清单。不要把这份清单画到图片里，也不要为了生成清单多出一张图。不能输出清单时仍只交付一张图片。
54. 此阶段仅生图，不声称图片有真实图层或已是可编辑 PPT。后续重建时，普通文字与代码应成为原生文本框，卡片/表格/网格/连接线成为原生对象，复杂插图分离为独立图片；不能采用整张原图铺底再覆盖文字的伪可编辑方式。

【生成前必须内部检查】

自行检查，不把检查过程放进图片：是否只一张；尺寸或比例准确且实际尺寸如实报告；没有总标题栏；仅标题下方主体；围绕用户内容、无新增主题；中文、代码、公式、数值、括号和运算符正确；流程关系、真假分支和循环回路正确；字号足够大；无 Logo、水印、无关装饰人物和干扰阅读的复杂背景；教学相关人物可原创；内容完整在画布内；文字和插图可区分；卡片、表格和连线结构清晰；适合插入 PPT 并后续重建。

如果同时上传图片和文字，理解素材教学内容并结合文字要求重新创作；只上传图片时先理解再提炼；只提供文字时照样生成原创教学视觉，无需等待插图。可以在主题内通俗改写、解释和创新构图，无法确认的事实、参数和技术关系不要编造。
